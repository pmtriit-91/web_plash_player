# Design Intent Runtime — Universal

## Purpose

This skill helps the agent reason about UI/UX quality without forcing any specific aesthetic.

It is universal and project-agnostic.

It must work across:
- dashboards
- landing pages
- developer tools
- mobile apps
- enterprise apps
- creative portfolios
- documentation sites
- SaaS products
- ecommerce
- admin consoles
- games
- data tools
- internal tools

## Core Rule

Do not impose a style.

Detect the design intent.

Then preserve, refine, or intentionally transform it based on user instruction.

## Design Intent Detection

Before changing UI, identify:

1. Product type
2. Target user
3. Current visual language
4. Interaction density
5. Brand/personality expectation
6. Functional priority
7. Existing design system or UI library
8. Whether the task asks for refinement or transformation

## Universal Quality Principles

Regardless of style, preserve:

- visual hierarchy
- spacing rhythm
- typography clarity
- interaction clarity
- accessibility
- responsive behavior
- consistency
- affordance
- performance
- maintainability

## Library Neutrality

UI libraries are implementation details.

Do not assume any one library implies a visual style.

Examples:
- component libraries can look corporate, playful, premium, minimal, or custom.
- utility CSS can look polished or messy.
- custom CSS can be expressive or unmaintainable.

Choose styling strategy based on project intent and constraints.

## When To Activate

Activate for:
- UI polish
- visual design
- UX layout
- style consistency
- component redesign
- landing/showcase pages
- dashboards
- interaction refinement
- user says UI feels generic, mechanical, boring, cramped, noisy, cheap, or inconsistent

Do not activate for:
- pure backend logic
- simple text typo
- simple import fix
- non-visual refactor
