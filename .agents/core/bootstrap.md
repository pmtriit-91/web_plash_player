# Bootstrap — V9.1.0

Use the smallest safe boot sequence.

1. Invoke the read-only lifecycle doctor.
2. Read `runtime-kernel.md`.
3. Apply `UNBOUND`, `BOUND`, or `DEGRADED` permissions before project context.
4. If `BOUND`, inspect Project Genesis source and projection health. Load
   constitutional claims only from a `confirmed` source with a matching bounded
   projection; otherwise expose state and reason codes without claim values.
5. If a project context manifest exists, run the read-only Context Memory doctor.
   Load hot context only when it is `FRESH`; its lifecycle is independent of Genesis.
6. Before a dependent major phase open, phase release, or final phase handoff, inspect
   the declared work-governance authority and verified hot context. If cumulative
   review is due, missing, or `REMEDIATION_REQUIRED`, select the reviewer workflow and
   block the transition until `PASS` or `PASS_AFTER_REMEDIATION`.
7. Before implementation mutation, inspect any repository-declared Capacity Gate and
   require a bounded envelope for outcome, writable scope, source/test size, cases,
   runtime/watchdog, checkpoint, and handoff. A crossed threshold returns
   `STOP_AND_SPLIT`; it never authorizes a larger implicit claim.
8. Resolve one internal workflow if a workflow is needed.
9. Resolve one primary capability if specialized guidance is needed.
10. Inspect current source and direct dependencies.
11. Execute only work authorized by the user.
12. Validate in proportion to risk and report evidence.

Do not scan all workflows or vendor skills. Do not load Project Memory before a
valid `BOUND` state and a `FRESH` Context Memory diagnosis. Never use a missing,
draft, stale, conflicting, contaminated, or projection-mismatched Genesis as
constitutional truth. Read-only forensic
inspection is allowed when explicitly authorized, but stale, conflicting, or
contaminated project context remains untrusted.

If the lifecycle engine or root bridge is unavailable, report the discovery
failure and stay in safe read-only mode.
